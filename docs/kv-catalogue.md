# Key-value catalogue

The normative list of the keys in the `kv` table, the application state that is
not in a table of its own. The table between the markers is generated by a scan
of every SQL write and delete of `kv` in `backend/` (and of the callbacks
`server.py` hands to it) with `python tests/test_key_value_service.py --write`;
a test fails when it is out of date or when a write has a key the scan cannot
read. A new key needs no entry: it appears here when its write is added.

- **Backup:** a backup is the whole database, so it holds every key.
- **Purge:** the confirmed local data purge deletes every row, then rewrites the
  keys marked `rewritten` in the Purge column.
- **Export:** the privacy export leaves out the keys marked `no`: the named
  credential and state keys, and every key ending in `_running` or `_status`.
- **Reset at start:** startup and restore set the keys marked `yes` again.
  `profile` is only set when absent.
